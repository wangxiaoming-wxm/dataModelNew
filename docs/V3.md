# V3 方案与复现

> 提交文件：`submissions/submission_v3.csv`  
> 诚实嵌套 OOF（20 个 block seed 均值）：**0.70124**（sd 0.00035）  
> 对照 V2（同仓库 `submissions/submission_v2.csv`，公开榜 0.70878）：嵌套均值 0.69824 → **+0.00301**

V3 不是换模型族，也不是刷超参。它在 V2 的同一套诚实协议与同一条预登记融合规则
（`views_max`）上，把三个主臂从 **5 折 × 12 种子**换成 **10 折 × 8 种子**。
每折多看约 11% 训练数据，三个主臂各自抬约 +0.002–0.003，融合跟着抬。

## 4. 从零重训（一条命令）

```bash
bash run_v3.sh
```

等价于：

```bash
export PYTHONPATH=src2:src3
# 三个主臂，各 8 个种子，10 折，单线程×4 并行
# main/d5, main/d6, alt/d6l6  → artifacts/worlds10/part_*.npz
bash -c '...'   # 见 run_v3.sh

# 合并
python3 src3/merge_seeds.py --world main --preset d5   --folds 10 \
    --dir artifacts/worlds10 --name cat_d5 --out artifacts/v3_f10
python3 src3/merge_seeds.py --world main --preset d6   --folds 10 \
    --dir artifacts/worlds10 --name cat_d6 --out artifacts/v3_f10
python3 src3/merge_seeds.py --world alt  --preset d6l6 --folds 10 \
    --dir artifacts/worlds10 --name cat_alt --out artifacts/v3_f10

# 组装 artifacts/v3（10 折主臂 + V2 遗留的弱臂/对照臂）
# 然后 fuse2 + audit
```

种子固定为 `21000..21007`。抖动流 offset 默认 `seed % 97 + 1`
（见 `src3/run_world.py`），与当时训练一致。

耗时参考（4 核、每进程 1 线程、四并行）：

| 臂 | 单种子 | 8 种子（墙钟，四并行） |
|---|---:|---:|
| `main/d5`（depth 5, 1000 树） | ~47 min | ~1.6 h |
| `main/d6`（depth 6, 700 树） | ~45 min | ~1.5 h |
| `alt/d6l6`（depth 6, 800 树） | ~40 min | ~1.4 h |
| 合计 | | **约 8–10 h** |

## 5. 协议红线（与 V2 相同，监督者强制）

1. 外层验证折上**不许**早停或做任何选择；树数开跑前定死。
2. 特征工程不许碰标签；分位切点 / 车型量纲 / 抖动流均为 label-free。
3. 融合规则先登记再看分；主报数字是**多 block seed 的嵌套均值**，不是单一种子。
4. 每次改完跑 `src3/audit.py`；打乱标签必须回落到 ~0.5。
5. 不要拿榜单分当调参反馈。

`src3/audit.py --target 0.99999` 会失败——这是设计如此，见 `docs/SUPERVISION.md`。
