## 1. 赛题、数据与信号结构

### 1.1 赛题
保单信息、车辆信息、匿名化数据；预测投保人未来一年是否索赔；AUC；提交 `id,label` 概率。

### 1.2 数据
- train 14930×45（44 特征 + label），正例 1497（10.02%）；test 6398×44。
- 目录：`/Volumes/pssd/app/ml/正式比赛/data/`（train.csv 5.9MB / test.csv 2.5MB / submit_sample.csv）。

### 1.3 信号结构（v2 数据结构逆向，多仓库独立验证）
来自 `dataModelNew-task-20260808-cursor/docs/DATA_STRUCTURE.md` 与 SOLUTION.md，zcode 侧独立复现吻合：
- **44 列里 27 列是匿名化噪声**：`V`、`x19`、`code`、`t3`、`cc`、`max_g`、`x0-x17` 都是 `source`（隐藏车型 ID，11 类）的确定性函数加均匀噪声（组内残差宽度精确等于 极差/√12）。
- `livability ≡ region`；`x20 ≈ 1.2·condition − 0.53 + U(−1.5,1.5)`；`x18` 无条件噪声。
- 噪声列单独/联合预测标签 = 随机水平（联合 LightGBM AUC 0.518，标准误 0.008）。
- 真正有信号的列：`days`、`region`、`condition`、`source`、`age_range`、8 个二值开关。
- 对抗验证 train vs test AUC = 0.4977：**无分布偏移可利用，无泄漏**。

### 1.4 单列信号天花板（多次独立测量）
| 特征 | 单列 AUC | 来源 |
|---|---:|---|
| `rate = days×(1 − cond 在 source 内秩)` | **0.622** | 全场最高 |
| `days / cond_r^0.75` | 0.6211 | v2 变换扫描 |
| `days × (1 − rank\|source)` | 0.6216 | v2 / zcode 探针 |
| `ratio = days / cond_r` | **0.620** | 全场最强简洁表达 |
| `days` | 0.5932 | 原始最强列 |
| `cond_r = condition / median\|source` | 0.5672 | v2 独有 |
| `condition`（原始） | 0.5324 | 量纲随车型差 3 倍 |
| x0-x20 | 0.49-0.53 | 噪声 |
| days mod 90 | 0.518 | 周期变换无信号 |

结论：**days×condition×source 是唯一信号轴**；任何新编码世界都必须以接近 0.620 的核心信号为前提，否则进 max 是负贡献。

## 2. 评估口径字典

| 口径 | 定义 | 谁在用 | 与 full-OOF 的关系 |
|---|---|---|---|
| 全量 OOF（full） | 融合 OOF 直接算 AUC | 所有人 | 基准 |
| 嵌套 5 块（zcode 系） | OOF 按 5 个连续块重排后算 AUC | v4_honest/v4_max3/v5_honest/v6 | ≈ full −0.0003 |
| 20-block 均值 | 20 个随机分块种子取均值 | v2/V3/V4 监督者 | 报告 mean±sd |
| 真嵌套选择 | 每折在预注册规则集上"内折选规则、held 折评估"，20 种子 | v3/V4/v4ext（fuse4）；v2 为 5 块嵌套选择（4 块选规则、1 块评估） | full − 选择乐观（v4ext 0.00048） |
| pooled（bag） | 多种子 OOF 秩平均后算 AUC | 各臂报告 | 部署代理指标 |
| LFO held-out | 4 折 fit 权重、第 5 折评估 | Phase2 | 过拟合检验 |
| 打乱标签 sanity | 标签置换后融合 AUC | 全部 | 应 ∈0.47-0.53 |

**ES-bias 实测**（同一特征、同折、只换停止方式）：
| 测量 | ES | 固定树 | 乐观 |
|---|---:|---:|---:|
| v2 主视图（zcode 侧，seed2026） | 0.689129 | 0.687675 | **+0.001454** |
| gap 视图（v2 侧） | 0.68800 | 0.68658 | **+0.00142** |
| es_bias.json（v4ext 审计引用） | 0.6871 | 0.68456 | **+0.00254** |

**结论**：任何含 `use_best_model` 的本地数字都要标注"乐观 +0.0015~0.0025"；测试预测仍诚实（ES 不看测试标签）。

### 5.1 根因分解：折数 vs 臂相关性（2026-08-11 新增，基于 23 臂独立复算）

用 v4text 目录下全部 23 个臂做受控对照（5 连续块口径，与各方案报告一致），分离"折数"与"臂相关性"两个变量：

| 方案 | 臂数 | avg_corr | nested(5块) | LB | gap |
|---|---:|---:|---:|---:|---:|
| v4_honest（mo8, ca8） | 2 | 0.958 | 0.69993 | 0.71104 | +0.01111 |
| v5_honest（+gap 臂） | 3 | 0.956 | 0.70253 | 0.71207 | +0.00954 |
| v4_max3（+ord ES 臂） | 3 | 0.959 | 0.70307 | 0.71222 | +0.00915 |
| v4ext（13 臂） | 13 | 0.973 | 0.70396 | 0.71123 | **+0.00727** |

**判别证据**：
- v4_honest → v5_honest（加 1 个 gap 臂，corr 0.94-0.97）：gap 从 +0.0111 缩到 +0.0095（−0.0016）→ **加臂会压缩 gap**，即使加的不是超高相关臂
- v4_honest → v4_max3（加 1 个 ES 臂）：gap 从 +0.0111 缩到 +0.0092（−0.0020）→ ES 臂的 nested 虚高额外压缩 gap
- V3（3 臂 10 折，cat_d5/d6/alt）：gap +0.0094 → 与 5 折 3 臂方案（+0.0092~0.0095）**无显著差异** → **折数本身不压缩 gap**
- v4ext（13 臂 avg_corr 0.973）：gap +0.0073 → 比任何 3 臂方案都小 → **高相关臂数量是压缩 gap 的主因**

**结论（修正后）**：
1. 加臂会压缩 gap（max-fusion 的固有特性），这是 max 选择偏差的表现
2. **折数本身不压缩 gap**（V3 10 折 gap +0.0094 ≈ 5 折 3 臂方案的 +0.0092-0.0095）
3. 高相关同族臂（corr>0.97）大量堆叠会**显著加剧** gap 压缩（v4ext 13 臂 gap +0.0073）
4. v4ext 失败的核心 = 10 个 corr>0.97 的同族臂把 OOF 的 max 推高 +0.0028，这种膨胀不迁移到 LB

> **自审修正**：本节早期版本曾用 20-seed 口径复算，得出"v5_honest 加臂 gap 不缩反升"的结论——这是口径错误（20-seed 与报告的 5 连续块口径不同）。用 5 连续块口径（与各方案报告一致）复算后，v5_honest gap 确实缩小了（+0.0111→+0.0095）。核心结论（折数不压缩 gap、高相关臂堆叠压缩 gap）不变，但控制变量实验的具体数值已修正。
