写给接手冲击第一名的人。这份文件回答四个问题：

1. 我是怎么想的、为什么走这条路；
2. 现在的架构长什么样、每一层在解决什么问题；
3. 我踩过和绕开了哪些坑（每条都附证据）；
4. 要夺冠还差多少、接下来具体怎么做，包括两套备用方案。

## 1. 先把差距量化清楚

| 项 | 值 |
|---|---|
| 本方案本地诚实 AUC（嵌套 OOF） | **0.69856** |
| 同口径重跑的 B7 `gap` 视图 | 0.69044 |
| B7 提交的公开榜分 | 0.70722 |
| 前三名公开榜分 | ≈ 0.715 |
| B7 旧口径本地分 | 0.702705（含 +0.0025 早停乐观，**不可比**） |

### 1.1 本地分和榜单分之间差了什么

两者不是同一个东西，差异由三部分构成，方向都是正的：

1. **测试端集成更强。** OOF 里每一行的预测来自训练了 80% 数据的模型，按种子平均；
   测试端的预测是 12 个种子 × 5 折 = 60 个模型平均。集成规模差一个数量级。
2. **公开榜是子集抽样。** 6398 行、约 640 个正例时 AUC 的抽样标准误约 0.011；
   如果公开榜只用一半数据，约 0.016。
3. 训练集和测试集同分布（对抗验证 AUC 0.4977），所以**没有**分布偏移这一项。

B7 那次的经验值：旧口径本地 0.7027 → 榜单 0.70722，差 +0.0045；
但旧口径本身高估了 0.0025，所以真实的"本地→榜单"偏移大约是 **+0.007 到 +0.013**，
中位数取 +0.010 比较稳妥。

### 1.2 所以要夺冠，本地需要多少

```
目标榜单 0.720  →  需要本地诚实 ≈ 0.710
目标榜单 0.716  →  需要本地诚实 ≈ 0.706
当前本地 0.69856
```

**还差 +0.007 到 +0.012。** 这是一个明确的、可以拿来做取舍的数字：
任何预期收益低于 +0.002 的改动都不值得单独投入，除非它能叠加。

### 1.3 一个必须承认的现实

前三名的 0.715 里也含着他们自己的那一份抽样噪声。有可能其中某一名的真实水平只有 0.705，
只是抽到了好的一半。**你无法通过刷榜区分这两种情况**——反过来，
如果你把本地做到 0.710，那么即使运气一般也大概率进前三。

所以策略是明确的：**只优化本地诚实分，不要看榜单调参。**

## 2. 解题思路：为什么走这条路

### 2.1 第一步是算信噪比，不是建模

14930 行、1496 个正例、AUC 在 0.70 量级。AUC 的标准误约 0.008。
这意味着：

- 单次 5 折 CV 上任何小于 0.008 的"改进"都不可信；
- 必须用**配对**的重复 CV（所有对照共用完全相同的折）才能看清 0.002 量级的差异；
- 应该优先去找 **≥0.005 量级的结构性改进**，而不是调超参。

这条判断决定了后面所有的时间分配：我几乎没花时间调超参
（`max_ctr_complexity` 扫了 2/4/6，差别 0.0005，扔掉；深度扫了 5/6/7，差别 0.003，
到噪声区间就停手），全部时间花在"这份数据里到底有什么"上。

### 2.2 第二步是问"数据里到底有多少信息"

上一版 B7 的做法是不断加特征块、加臂、加种子，本质是在假设"信息还在，只是没榨出来"。
我先反过来验证这个假设，方法是逐列检查生成机制。结果发现假设错得很厉害：

**44 个特征里有 27 列是匿名化噪声。**

`source`（11 类）是隐藏的车型 ID。`V`、`x19`、`code`、`t3`、`cc`、`max_g`、`x0`–`x17`
都是它的确定性函数加**均匀噪声**——每一列的组内残差宽度精确等于 `极差/√12`
（`cc` = 车型常数 + `U(-50,50)`，`max_g` = 车型常数 + `U(-10000,10000)`，
`x0`–`x16` = 车型常数 + `U(-0.05,0.05)`）。
另外 `livability` ≡ `region`，`x20` ≈ `1.2·condition − 0.53 + U(−1.5,1.5)`，`x18` 是无条件噪声。

把这些残差单独拿去预测标签，24 列的 `|AUC − 0.5|` 最大值是 0.0152，
而随机置换 200 次的 p95 是 0.0159；一起喂给 LightGBM 做 5 折 CV 得到 0.518。**全在噪声带内。**

真正带信息的只有 **13 列**：`days`、`region`、`condition`、`source`、`age_range`
和 8 个二值开关。`month` / `version` / `grades` 的诚实折外目标编码 AUC 都在 0.50 附近。

### 2.3 第三步是找被量纲掩盖的信号

有效特征只有 13 列，那就必须把每一列榨干净。最大的一处是 `condition`：

各车型的 `condition` 量纲差 3 倍以上（`CAR_1` 中位数 0.21，`CAR_8` 中位数 1.15），
原始列把"车型差异"和"个体差异"混在了一起。逐对交互筛查里，
`source × condition` 的增益是所有二阶交叉里最大的一项（**+0.0292**，第二名只有 +0.0129）。

按车型归一化，再和 `days` 组合成一个速率：

```
cond_r = condition / median(condition | source)
ratio  = days / cond_r
```

| 特征 | 单列 AUC |
|---|---:|
| `days`（原始最强列） | 0.593 |
| `condition` | 0.532 |
| `cond_r` | 0.567 |
| **`ratio`** | **0.620** |

`ratio` 比任何原始列都强。对 `days`/`cond_r`/`age`/`grade` 之间约 40 种比值、乘积、
秩差、以及按 6 种分组的三类归一化都扫过，峰值就是它。

### 2.4 第四步：发现这题的真正机制

这是整个项目最重要的一个认知转折。

按 2.2 的结论，那 27 列噪声应该全删。**实测却相反**：在干净特征集上把它们加回去，
CatBoost 的单模型 OOF 从 0.6793 跳到 **0.6892（+0.010）**，是全项目单笔最大收益。

原因不是它们有信息，而是它们是同一批真实交互的**不同扰动离散化**：

- `x20 × source` 就是 `condition × source` 的一个加噪版本；
- `t3 × days_bin` 就是 `source × days_bin` 的一个随机细分（`t3` = 车型常数 + 均匀噪声，
  作为类别列等于把每个车型随机切成 31 份）；
- `livability × age` 就是 `region × age` 的一个副本。

CatBoost 对每个类别列都会算有序目标统计量（ordered target statistics），
本质是一个带正则的目标编码。多个扰动版本并存，等于让树集成对同一个统计量做了平均，
方差下降。**这题的瓶颈不是"信息不够"，而是"目标编码的方差太大"。**

想通这一点之后，后面所有的动作都是同一个主题的延伸：

- `src2/jitter.py`：用行 `id` 的哈希造确定性扰动流，主动生成受控的重编码视图（再 +0.001）；
- 每个种子换一套不同的扰动流，给 bagging 再叠一层多样性；
- `features.build_alt` / `build_alt2`：把同样的信息用完全不同的方式再表达一遍
  （换归一化基准、换分箱数、换交叉清单），做成独立的"编码世界"；
- 融合时用 `max` 而不是平均。

**这也是判断"下一步该做什么"的标尺**：能增加编码多样性的动作有回报，
换模型族、加种子、调超参都没有（见第 5 节的证据）。

## 3. 架构

三层，每一层解决一个不同的问题。

```
第 0 层  数据理解                docs/DATA_STRUCTURE.md
         ├─ 27 列噪声识别        决定哪些列进 CatBoost（做抖动）、哪些列进 LGB/GLM（不能进）
         └─ cond_r / ratio       全数据最强的两个构造特征

第 1 层  编码世界（Encoding World）        src2/features.py
         ├─ main   condition 按车型中位数归一化 · 分箱 (5,10,20,40) · 45 个手工交叉
         ├─ alt    condition 按车型内秩归一化   · 分箱 (7,13,25)    · 另一套交叉
         ├─ alt2   condition 按 region×source 标准化 · 分箱 (4,9,16) · 又一套交叉
         └─ 每套都叠加：主办方噪声视图 + N 套自造抖动重编码（每个种子一套不同的）
                                                    src2/features.add_noise_view
                                                    src2/jitter.add_jitter_views

第 2 层  臂（Arm）                          src2/arms.py
         ├─ cat_d5   CatBoost depth 5 / 1000 树   在 main 世界上
         ├─ cat_d6   CatBoost depth 6 /  700 树   在 main 世界上（bagging_temperature=1）
         ├─ cat_alt  CatBoost depth 6 /  800 树   在 alt 世界上
         ├─ cat_alt2 CatBoost depth 6 /  900 树   在 alt2 世界上（当前未进最终融合）
         ├─ gap      CatBoost 在上一版 B6 视图上，用新口径重跑（对照 + 多样性）
         ├─ lgb_te   LightGBM + 折内嵌套目标编码   src2/te.py
         └─ glm      样条 + 目标编码 logit 的 L2 逻辑回归
         每个臂：重复分层 5 折 × 12 个种子；OOF = 按种子秩平均；test = 60 个模型秩平均

第 3 层  融合                                src2/fuse.py
         ├─ 16 条预先登记的权重规则（含 max 族）
         ├─ 嵌套选择：OOF 切 5 个外层块，在 4 块上选规则、在第 5 块上应用
         └─ 主报数字 = 这样拼出来的预测上算的 AUC（不含选择乐观）
```

设计上的三个要点：

- **第 1 层才是可扩展的维度。** 加一个编码世界比加一个模型族有用得多。
  架构上专门把"编码世界"和"模型臂"拆开，就是为了让加世界这件事成本最低——
  写一个 `build_xxx` 函数 + 一个 `xxx_frame` 入口，`run_oof.py --view xxx` 就能跑。
- **分段运行 + 合并。** `run_oof.py` 每次只跑 4 个种子，`--stream-base` 决定这一段用哪族抖动流，
  `merge_runs.py` 按等权平均合并（每段模型数相同时是精确池化）。
  好处是断点续跑只损失一段，而且随时可以往上加种子/加世界。
- **融合规则先登记后打分。** 这是唯一能让"最终数字"可信的办法。

## 4. 我避开的坑（每条都有证据）

### 4.1 协议层面

**① 在外层验证折上早停。** 上一版就栽在这里：验证折同时被用于按 AUC 挑迭代数、
又被用于产生 OOF 预测。同折同参实测乐观 **+0.00254**
（AUC 早停 0.68710 / Logloss 早停 0.68692 / 固定 500 树 0.68456，见 `artifacts/v2/es_bias.json`）。
数值不大，但它让本地分失去了做决策的资格——你没法用一把会自己变形的尺子去比较两个方案。
本分支所有对比都用固定树数。

**② 按 OOF 在几个已完成的运行之间挑最好的那个。** 三个主臂从 8 个种子加到 12 个后，
`views_max` 从 0.69958 变成 0.69910。按分数应该交 8 种子那版——但那正是选择性乐观。
更多种子在期望上不会更差，所以交的是 12 种子版。**这类"看起来无害"的选择是本地分虚高的主要来源。**

**③ 把公开榜当调参反馈。** 抽样标准误 0.011–0.016，照着它调等于在拟合噪声。

**④ 全局目标编码。** 所有目标编码都由拟合行内部再切一层 K 折产生（`src2/te.py`），
任何一行不会看到自己的标签。

**⑤ 在 train+test 上拟合变换却不做验证。** 我确实在 train+test 上拟合了分位切点、
车型量纲、频次编码、抖动流——因为它们 label-free，这样做是安全的。
但"应该安全"不等于"确实安全"，所以有打乱标签对照：
把标签随机置换后整条管线回落到 AUC **0.4983**。每改一次特征都要重跑这一条。

### 4.2 建模层面

**⑥ 相关性 0.997 的伪多样性。** `cat_d5` 和 `cat_d6` 只差深度，相关 0.997，
融合几乎无增益（`cat_pair` 0.69509 对 `cat_d5_only` 0.69506）。
真正的多样性来自换编码世界（`cat_alt` 相关 0.954，把融合抬到 0.69910）。

**⑦ `max` 融合对弱臂敏感。** 第三个世界 `cat_alt2` 解耦得很好（相关 0.950）
但单臂弱了 0.004，放进 `max` 反而把 0.69910 拉到 0.69837。
原因是 `max` 取的是"最敢下注的那个视图"，弱臂偶尔会把某些负样本顶到高位。
**加世界的前提是新世界必须和现有臂同等强度。**

**⑧ 盲目扩交叉。** 手工精选 42 个类别列时是 0.68210（bag）；
按基列全配对扩到 57 / 87 / 124 / 170 列，分别掉到 0.68080 / 0.67885 / 0.67984 / 0.67775。

**⑨ 指望 CatBoost 自己组合类别列。** `max_ctr_complexity` 扫 2/4/6，差别在 0.0005 内；
而手工把交叉物化出来直接 +0.017。它的自动组合是贪心的，
不会主动去找 `condition × source` 这种需要先归一化才显形的交互。

**⑩ 换模型族翻盘。** LightGBM 0.671、GLM 0.665、（旧版测过的）XGBoost 0.65、EBM 0.64、MLP 0.57，
都比 CatBoost 差 2 个点以上。差距全部来自有序目标统计量。

**⑪ 去挖 latent 里的"隐藏信号"。** `x0`–`x18` 的残差、`days` 的周期性（mod 7/30/90/365）、
`id` 哈希、行序、计数编码——全部验证过，全部无信号。清单见 `docs/EXPERIMENTS.md` 第 7 节。

## 5. 模型现状与容量分析

### 5.1 各臂强度与解耦度

| 臂 | 编码世界 | 种子数 | bagged OOF AUC | 与 cat_d5 的秩相关 |
|---|---|---:|---:|---:|
| `cat_alt` | alt | 12 | 0.69508 | 0.954 |
| `cat_d5` | main | 12 | 0.69506 | — |
| `cat_d6` | main | 12 | 0.69491 | 0.997 |
| `cat_alt2` | alt2 | 8 | 0.69100 | 0.950 |
| `gap` | B6 视图 | 4 | 0.69044 | 0.971 |
| `lgb_te` | main（去噪声列） | 8 | 0.67110 | 0.929 |
| `glm` | main（去噪声列） | 8 | 0.66489 | 0.898 |

**理想的下一个臂长什么样：强度 ≥ 0.694，与现有臂相关 ≤ 0.95。**
现在没有任何一个臂同时满足这两条——`cat_alt` 满足强度但相关 0.954 已经是最好的；
`glm` 相关只有 0.898 但弱了 0.030。这个二维平面上的空白区就是全部的机会。

### 5.2 增益是怎么一步步来的

| 阶段 | 单模型 OOF | bag |
|---|---:|---:|
| 朴素 CatBoost（全部原始列） | 0.65384 | — |
| 删掉噪声列 | 0.66230 | — |
| 加 `cond_r` / `ratio` + 手工交叉 | 0.67934 | 0.68225 |
| **加回噪声列（编码平均）** | **0.68921** | **0.69209** |
| 加自造抖动重编码 | 0.69028 | 0.69386 |
| 12 种子 bagging | — | 0.69506 |
| 三个编码世界 `max` 融合 | — | **0.69910 / 嵌套 0.69856** |

看这张表能得到一个很直接的判断：**从 0.662 到 0.699 的 3.7 个点里，
有 2.3 个点来自"编码"（交叉 + 噪声视图 + 抖动 + 多世界），只有 0.8 个点来自特征本身。**

### 5.3 学习曲线诊断

见 `logs/screening/exp16_capacity.log`。方法：固定验证折不变，只缩小拟合行数。

固定验证折不变，只缩小拟合行数（5 折 × 2 重复，主编码世界，CatBoost depth 5）：

| 拟合行数 | 占比 | 单模型 OOF | bag |
|---:|---:|---:|---:|
| 4778 | 40% | 0.64927 | 0.65886 |
| 7166 | 60% | 0.66971 | 0.67694 |
| 9555 | 80% | 见日志 | 见日志 |
| 11944 | 100%（5 折） | 见日志（生产运行里同配置约 0.690 / 0.694） | |
| 13437 | 100%（**10 折**） | 见日志 | |

> 完整结果在 `logs/screening/exp16_capacity.log`（80% / 100% / 10 折三行在我交付时仍在跑，
> 接手后直接看这个文件即可，脚本是 `exp/exp16_capacity.py`）。

**已经能下的结论：曲线在陡峭上升段。** 从 4778 行到 7166 行（多 2388 行）
单模型 AUC 涨了 **+0.020**；从 7166 行到生产配置的 11944 行（多 4778 行）又涨了约 **+0.020**。
换算下来在这个区间里**每多 1000 行训练数据大约值 +0.004 ~ +0.008 AUC**。

这说明**我们是被"每个模型看到多少数据"卡住的，不是被模型容量卡住的**。
这也解释了为什么调深度、调 `max_ctr_complexity`、加交叉都没用——
那些都是在动模型容量，而瓶颈不在那儿。

### 5.4 天花板在哪

综合几个信号：

- 有效特征只有 13 列，其中 `ratio` 单列就有 0.620，`region` 0.547，其余都在 0.52 附近；
- 主要的二阶交互只有一个显著项（`source × condition`），其余都在噪声带内；
- 单模型无论怎么弄都卡在 0.690 附近，超过这个数只能靠集成。

我的判断是：**单模型的信息上限大约在 0.69–0.70，集成的上限大约在 0.705–0.712。**
本地 0.710 是够得着但需要认真做的目标，0.72 以上大概率超出这份数据的信息量。
这也意味着榜单上 0.72+ 的分数里必然含有相当比例的运气成分。

## 6. 主方案路线图（按性价比排序）

每一项都给出：做法、预期收益、成本、风险、怎么验证。
**做任何一项之前，先跑一遍 `src2/verify.py` 记下基线，做完再跑一遍。**

### P0. 把 5 折换成 10 折（学习曲线已经支持，先做这个）

**为什么这条排第一。** 5 折时每个模型看 11944 行，10 折时看 13437 行，多 1493 行。
按 5.3 的斜率（每 1000 行约 +0.004 ~ +0.008），**预期收益 +0.003 ~ +0.008**，
是路线图里单笔最大的一项，而且不需要任何新想法。

这也和上一版的一条观察对上了：B7 的 `plus` 臂用的是 10 折 × 4 种子，
他们的记录里写着「plus 只跑 5fold×1seed 会严重低估（差约 0.008–0.01）」。
当时他们把这归因于种子数，但从学习曲线看，**折数才是主因**。

**做法。** `run_oof.py` 已经有 `--folds` 参数，直接：

```bash
PYTHONPATH=src2 python3 src2/run_oof.py --folds 10 --seeds 20260 20261 --stream-base 0 --out artifacts/v3a
```

**成本。** 机时增加 80%（10 个模型而不是 5 个）。`cat_d5` 从 260 秒/种子变成约 470 秒/种子。
因为机时翻倍，可以把种子数从 12 降到 6–8——第 5.2 节的证据表明种子在 8 之后已经饱和，
而折数还在斜率上，这个交换是划算的。

**风险。** 低。10 折的 OOF 每折只有 1493 行、约 150 个正例，
单折 AUC 的方差会变大，但**池化后的 OOF 方差不变**（还是 14930 行打分），所以主报数字照样可靠。

**怎么验证。** 先用 2 个种子跑 10 折，和现有 12 种子 5 折的 `cat_d5`（0.69506）比单臂 bagged OOF。
注意种子数不同不能直接比，要用同样的种子数对照——
先跑 `--folds 5 --seeds 20260 20261`（约 9 分钟）拿到 2 种子的 5 折基线，再和 2 种子的 10 折比。

### P1. 再造 2–3 个"编码世界"（最高确定性）

**做法。** 照着 `features.build_alt` 的样子写新的 `build_*`，
关键是**保住 `cond_r` / `ratio` 这两个核心信号，只换表达方式**：

- 换归一化基准：分位数映射到正态、按 `source × age` 分组、稳健 z（中位数/MAD）、
  按 `region` 二次归一化；
- 换分箱：等宽箱、树诱导箱（用一棵浅树在 `days` 上切）、对 `ratio` 用对数等距箱；
- 换交叉清单：保住 `condition × source` 这一族，其余重新挑；
- 换抖动参数：`n_views`、`n_bins`、扰动幅度、`n_sub`。

**预期收益。** 第二个世界带来了 +0.004（`cat_pair_max` 0.69539 → `views_max` 0.69910）。
第三、第四个的边际会递减，但如果每个都做到 0.694 以上，合计 +0.003 ~ +0.006 是合理预期。

**成本。** 每个世界：写代码 + 8 个种子约 30 分钟机时。

**风险。** 新世界弱于 0.694 就会拖垮 `max`（见坑 ⑦）。
**先用 4 个种子筛一遍，达标了再补到 12 个种子。**

**怎么验证。** 单臂 bagged OOF ≥ 0.694 且与现有臂相关 ≤ 0.96，
然后看 `fuse.py` 的 `nested_oof_auc` 是否上升。

### P2. 把 `lgb_te` 和 `glm` 做强

**做法。** 这两个臂与主臂的相关只有 0.898–0.929，是全场最解耦的，
可惜太弱（0.665 / 0.671）所以进融合是负贡献。如果能做到 0.688 以上，
它们的贡献会超过再加一个 CatBoost 世界。

- `glm`：现在只有 5 个样条项 + 目标编码 logit。可以加张量交互
  （`source` × `log_cond_r` 的样条积）、按 `region` 的分层随机效应、
  或者直接换成带交互项的 GAM；
- `lgb_te`：目标编码的平滑系数、编码列清单、`min_child_samples` 都没调过。
  另外可以给 LightGBM 也做"编码平均"——用多套不同随机种子的目标编码取平均。

**预期收益。** 不确定，但天花板高：一个 0.690 且相关 0.90 的臂，
在 `max` 融合里的贡献会明显大于一个 0.695 且相关 0.955 的臂。

**成本。** 这两个臂各只要 3 秒/种子，迭代极快，几乎不花机时，花的是想法。

### P3. 树数随机化，制造"合法的"早停多样性

**做法。** 上一版有一处没对齐：他们的 gap 臂 8 种子是 0.69868，
减去实测的 +0.0025 偏差后是 0.6962，仍比我诚实重跑的 gap 臂（外推 8 种子约 0.692）高约 0.004。
其中一个可能的原因是：**早停让每个模型的树数各不相同，这本身给 bagging 增加了多样性。**

这个效应可以在不偷看验证折的前提下复现：给每个模型从一个预先定好的区间
（比如 300–1200）里随机抽一个树数。

**预期收益。** 如果那 0.004 里有一半来自这个机制，就是 +0.002。

**成本。** 改 `arms.py` 里几行，重跑一遍主臂，约 35 分钟。

**风险。** 低。这不涉及任何标签信息。

### P4. 增加折内的编码平均次数

**做法。** 现在每个模型看 4 套抖动视图（`n_views=4`）。exp14 试过 6 套反而掉 0.002，
但那是在**同一个模型**里堆更多列。另一条路是**同一折训练多个模型、各看一套不同的抖动**，
然后在折内平均——这和堆列不是一回事。

**预期收益。** +0.001 ~ +0.002。

**成本。** 机时线性增长。

### 路线图小结

| 项 | 预期收益 | 机时 | 确定性 |
|---|---:|---:|---|
| P0 10 折 | +0.003 ~ +0.008 | +80% | 高（学习曲线支持） |
| P1 再造 2–3 个编码世界 | +0.003 ~ +0.006 | 每个约 30 min | 高 |
| P2 做强 lgb/glm | +0.002 ~ +0.005 | 几乎为零 | 中 |
| P3 树数随机化 | +0.002 | 35 min | 中 |
| P4 折内编码平均 | +0.001 ~ +0.002 | 线性 | 中 |

全部做完的合理预期是本地 **0.705 ~ 0.710**，对应榜单中位数 **0.715 ~ 0.720**。
这条路上没有任何一步需要作弊或刷榜。

## 7. 备用方案 A：编码世界工厂（把 P1 规模化）

如果 P1 手工造世界的收益确认了，就值得把它自动化。

**思路。** 不再手工设计每个世界，而是**参数化地随机生成**几十个候选世界，
按"强度 + 解耦度"自动筛选，再做大规模融合。

**实现。**

1. 把编码世界的设计空间参数化：
   ```
   归一化方式  ∈ {median_ratio, rank, zscore, quantile_normal, robust_z}
   归一化分组  ∈ {source, source×region, source×age}
   分箱数      ∈ {(4,9,16), (5,10,20,40), (7,13,25), (6,12,24), ...}
   交叉清单    从一个候选池里随机抽 20–30 个
   抖动参数    n_views ∈ {2,3,4}, n_bins ∈ {7,10,13}, 幅度 ∈ [2,4]
   ```
2. 随机采样 30–50 个配置，每个用 **2 个种子**快速筛（约 6 分钟/个，合计 3–5 小时）；
3. 保留满足「bagged OOF ≥ 0.692」且「与已选世界的最大相关 ≤ 0.96」的，
   用贪心前向选择挑出 5–8 个；
4. 选中的补到 12 个种子，做 `max` 或加权 `max/mean` 融合。

**预期收益。** 这是最有可能把本地推到 0.705+ 的一条路。
理由是第 5.2 节的表：这份数据的增益来源集中在编码多样性上，而手工造世界的产能是瓶颈。

**风险。** 从 30–50 个候选里挑 5–8 个，是一次**有选择性的操作**，会引入乐观。
必须用嵌套的方式做：在外层折上做世界的选择，在留出块上评估。
`fuse.py` 的嵌套框架可以直接扩展成这个形式。**这一步做不干净，整份成绩就废了。**

**机时。** 筛选 3–5 小时 + 最终训练 3 小时。

## 8. 备用方案 B：换范式——参数化模型 + 半监督表示

这条路和方案 A 正交，可以并行。它赌的是另一件事：
**有效特征只有 13 列、样本只有 15k 时，参数化模型的方差可能比树模型小。**

### B1. 分层贝叶斯 / 正则化 GAM 作为主臂

现在的 `glm` 只是个带样条的逻辑回归，做得很粗。认真做的话：

```
logit(p) = f₁(log_days) + f₂(log_cond_r) + f₃(log_ratio)
         + u_region + u_source + u_region×source        （分层随机效应，带收缩）
         + g(log_cond_r) × source                        （张量交互，这是最强的那个交互）
         + β·binaries + u_bin_pattern
```

用 `pyGAM`、`statsmodels` 的 GLM + 手写惩罚，或者 `numpyro`/`pymc` 做完整的分层模型。
分层随机效应对 `region`（20 类）、`source`（11 类）这种中等基数的列有天然的收缩，
不需要目标编码，也就不存在目标编码的方差问题——而这恰恰是树模型在这题上的瓶颈。

**为什么值得赌。** 第 2.4 节的结论是"瓶颈在目标编码的方差"。
分层模型是从根子上解决这个问题的另一条路，而不是靠平均去掩盖它。
如果它能做到 0.690，它与 CatBoost 的相关大概率在 0.88–0.92，
在 `max` 融合里的价值会非常大。

**风险。** 需要把交互结构写对，工作量比造一个编码世界大得多；可能做不到 0.690。

### B2. 用 test 特征做无标签的表示学习（transductive，完全合法）

测试集的**特征**是给定的，用它做任何不涉及标签的事都不算作弊
（我已经在用：分位切点、车型量纲、频次编码都是在 train+test 上拟合的）。
还没被利用的：

- 在 21328 行全量上训练一个 **entity embedding 自编码器** 或
  **对比学习**（同一行的两个抖动视图互为正样本），
  把 `region` / `source` / `bin_pat` / 各种交叉映射成低维稠密向量，再喂给 GBDT；
- 或者更简单：对全量做 **类别列的共现矩阵 + SVD**，得到每个类别的向量表示。

**为什么可能有用。** 这等于用无标签数据给高基数交叉列学一个先验的相似性结构，
让目标编码不必从零开始估计每个格子——又是在解"目标编码方差"这个核心问题。

**风险。** 自监督在 15k 行的表格数据上经常什么都学不到。先做 SVD 版本（一小时内能验证）。

### B3. 目标编码的贝叶斯化

现在的平滑是固定系数（`smoothing=30`）。可以改成**经验贝叶斯**：
从数据估计每个交叉列的先验方差，按各自的可靠性自适应收缩。
对 `bin_pat`（256 类）、`d5_reg_src`（1000+ 类）这种稀疏交叉，
自适应收缩比固定系数应该明显更好。改动很小，值得先试。

## 9. 如果要赌：高风险选项（明确标注）

这些**不建议**在没有充足验证的情况下用于最终提交，列出来是为了完整。

- **只交 `max` 融合、不做保底。** `max` 族在本地是最好的（0.69910 对加权平均的 0.69716），
  但它的方差也更大。如果你只有一次提交机会且极度厌恶风险，
  `views_half`（加权平均）本地低 0.002，但榜单方差更小。
- **用更激进的规则集做嵌套选择。** 规则从 16 条扩到 50 条，
  嵌套选择的方差会上升，本地数字会虚高。不要。
- **半监督伪标签。** 用测试集的预测当软标签再训练。在同分布、
  且模型 AUC 只有 0.70 的情况下，这基本上是在放大自己的错误。不建议。

## 10. 算力与时间预算

本项目全程在 **4 核 CPU、15 GB 内存**上完成，无 GPU。参考耗时：

| 动作 | 耗时 |
|---|---|
| 构造一个编码世界的特征帧（21328 行） | 1 秒 |

然后把机时全部投给 P1 / 方案 A。
