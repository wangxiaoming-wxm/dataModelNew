# 数据生成结构逆向分析

> 本文是这一版方案的地基。所有结论都可以用 `eda/` 下的脚本复现，且**只用到特征列本身，没有任何一步依赖 test 标签或榜单反馈**。

赛题给了 44 个特征列，看上去信息量很大。实际上其中**超过一半是匿名化噪声**，
它们对标签的预测力严格等于零。把这件事搞清楚，是这一版能超过 B7 的根本原因。

---

## 1. `source` 是隐藏的"车型 ID"，一大批列都是它的噪声副本

`source` 只有 11 个取值（`CAR_0|ENG_709` 等）。按 `source` 分组后：

| 列 | 组内标准差 | 组内极差 | 判定 |
|---|---:|---:|---|
| `V` | 0.00087 | 0.00319 | = 车型常数 + `U(-0.0016, 0.0016)` |
| `cc` | 28.74 | 103.5 | = 车型常数 + `U(-50, 50)` |
| `max_g` | 5748 | 20695 | = 车型常数 + `U(-10000, 10000)` |
| `x0`–`x16` | 0.0288 | ≈0.103 | = 车型常数 + `U(-0.05, 0.05)` |
| `x17` | 0.00581 | 0.0210 | = 车型常数 + `U(-0.0105, 0.0105)` |
| `t3` 数值部分 | 0.0866 | 0.30 | = 车型常数 + `U(-0.15, 0.15)` |

均匀分布的标准差是 `极差/√12`，上表每一行都精确吻合，所以这些残差是**人为加上去的均匀噪声**，不是数据自身的变异。

另外两个是完全确定的函数关系：

- `x19 = round(V, 2)²`，16 个取值，与 `source` 一一对应（其中 5 个车型各再分裂成两档）；
- `code`（A/B/C/D）在每个 `source` 内只有 1 个取值；
- `t3` 的后缀字母（E/M/P）在每个 `source` 内也只有 1 个取值。

**结论：`V`、`x19`、`code`、`t3`、`cc`、`max_g`、`x0`–`x17` 加起来 27 列，
携带的信息量不超过 `source` 这一个 11 类的列。**

## 2. `livability` 是 `region` 的函数

20 个 `region` 对应 22 个 `livability` 取值，交叉表基本是对角阵（只有约 0.1% 的行错位）。两者是同一个变量。

## 3. `x20` 是 `condition` 加均匀噪声

固定 `condition` 在一个窄区间内，`x20` 的条件分布是**宽度恰好 3.0 的均匀分布**，
中心随 `condition` 线性移动（斜率 ≈ 1.2）：

| condition 区间 | x20 最小 | x20 最大 | 宽度 |
|---|---:|---:|---:|
| [0.40, 0.45) | −1.52 | 1.48 | 3.00 |
| [0.90, 0.95) | −0.92 | 2.08 | 3.00 |
| [1.40, 1.45) | −0.32 | 2.68 | 3.00 |

即 `x20 ≈ 1.2·condition − 0.53 + U(−1.5, 1.5)`，量化到 0.04 的网格上。

## 4. `x18` 是无条件噪声

与所有列的相关系数都接近 0，组内/组外标准差之比 1.036，单变量 AUC 0.5055。

## 5. 决定性检验：这些残差对标签有没有预测力？

把上面每一列的"组内残差"单独拿去算 AUC，并和随机置换的基准比较：

```
残差列（24 个）的 |AUC − 0.5| 最大值 = 0.0152
随机置换 200 次的 |AUC − 0.5|：均值 0.0064，p95 = 0.0159，最大 0.0289
```

**全部落在噪声带内。** 再把 24 个残差列一起喂给 LightGBM 做 5 折 CV，
得到 AUC = 0.518（AUC 的标准误约 0.008），同样不构成有效信号。

## 6. 真正携带信号的列

用**诚实的折外目标编码**（而不是会虚高的全量编码）测单列 AUC：

| 列 | 诚实 OOF-TE AUC | 备注 |
|---|---:|---|
| `days` | 0.593 | 最强的连续变量，随 days 增大风险单调上升，末端回落 |
| `region` | 0.547 | 真实的地域效应 |
| `condition` | 0.532 | **必须先按 `source` 归一化**，见下节 |
| `source` | 0.522 | 车型效应 |
| `age_range` | 0.516 | |
| 8 个二值开关 | 0.51 左右 | 组合成 8 位模式后有额外交互 |
| `version` | 0.501 | 基本是噪声 |
| `month` | 0.502 | 基本是噪声 |
| `grades` | 0.498 | 基本是噪声 |

`version` 各档的标签率区间是 0.070–0.136，每档约 240 行；在 p=0.1 下单档标准误约 0.019，
19 个档位的极差期望本来就有 3.4 个标准误，所以这个"差异"用噪声就能解释。`month`、`grades` 同理。

## 7. 最关键的一处结构：`condition` 需要按车型归一化

各车型的 `condition` 量纲差了 3 倍以上：

| source | condition 中位数 |
|---|---:|
| `CAR_1|ENG_591` | 0.210 |
| `CAR_5|ENG_062` | 0.708 |
| `CAR_2|ENG_262` | 0.904 |
| `CAR_8|ENG_843` | 1.148 |

所以原始 `condition` 把"车型差异"和"个体差异"混在一起。做交叉筛查时，
`source × condition` 的交互增益是所有二阶交叉里最大的一项（+0.0292，
即交叉项的 AUC 0.5954 对比两个主效应可加时的 0.5661）。

归一化之后单列 AUC 立刻提升：

| 特征 | AUC |
|---|---:|
| `condition` | 0.532 |
| `condition / median(condition \| source)` | **0.567** |
| `rank(condition) within source` | 0.565 |

进一步地，把它和 `days` 组合成一个"速率"：

```
cond_r = condition / median(condition | source)
ratio  = days / cond_r
```

**`ratio` 的单列 AUC = 0.620**，比原始最强列 `days`（0.593）还高，
是整个数据里最强的单一排序变量。（对 `days`、`cond_r` 的幂次、秩变换、
再按 region 二次归一化等 30 余种变体做过扫描，都没有超过这个组合。）

## 8. 训练集和测试集同分布

对抗验证（用全部特征去区分 train / test）的 AUC = **0.4977**，
说明这就是一次完全随机的切分。因此本地诚实 CV 与榜单分之间不存在分布偏移，
差异只来自"榜单是测试集的一个子集"带来的抽样噪声（6398 行、约 640 个正例，
AUC 的标准误约 0.011；若公开榜只用一半，则约 0.016）。

另外确认无可利用的泄漏：`id` 是纯随机 16 位十六进制（`int(id,16)` 的 AUC 0.494），
行序无信号（AUC 0.491），train/test 无重复行。

## 9. 一个反直觉但重要的现象：噪声列仍然值得放进 CatBoost

既然 `x19`/`x20`/`t3`/`livability` 不含独立信息，直觉上应该全部删掉。
实测却相反——在干净特征集之上把它们加回去，CatBoost 的单模型 OOF 从 **0.6793 提升到 0.6892**。

原因不是它们有信号，而是它们是同一批真实交互的**不同扰动版本**：
`x20 × source` 是 `condition × source` 的一个加噪离散化，
`t3 × days_bin` 是 `source × days_bin` 的一个随机细分。
CatBoost 对每个类别列都会算有序目标统计量（ordered target statistics），
多个扰动版本并存等于让树集成对同一个统计量做了平均，从而降低方差。

这个机制是可以主动复现的：`src2/jitter.py` 用行 `id` 的哈希造出确定性的
`U[0,1)` 扰动流，生成受控的重编码视图，再叠加约 +0.0010。
每个种子用不同的扰动流，等于给 bagging 集成又加了一层多样性。

**但这不改变第 5 节的结论**：这些列本身对标签零预测力，
它们的作用纯粹是正则化/方差平均。因此 LightGBM 与 GLM 臂里把它们全部剔除
（这两个模型没有有序目标统计量来保护自己，喂噪声只会过拟合）。
