# fp_v8 独立审核报告

**审核对象** `vz20/next_submit/submission_fp_v8_champion.csv`
SHA256 `fa2a06f4ed9af099e37225a2a9ff2e10e0a0a7979ac9c7e5dfacdcdde5866d67`

**声称** OOF 0.77016 / nested 0.77033，配方 `0.80*v7_cross30 + 0.20*bytepair_mean`

## 裁决

**fp_v8 严重过拟合。它声称的 0.77 里没有任何一点是可迁移的。**
所谓 "nested" 不是 nested，声称的 id 增益在随机置乱 id 上可以**逐位复现**。

复算脚本：`vz20/audit/e1_repro_and_nested.py`、`e2_crosshalf.py`、`e3_permutation_null.py`、
`e4_diagnostics.py`、`e5_spearman.py`；数字落在 `vz20/artifacts/vz20/e*.json`。

## 1. "nested" 是把做好的 OOF 再切五块，不是 nested

`fuse_fp_v8.py:164-165`：

```python
skf = StratifiedKFold(5, shuffle=True, random_state=2026)
nest = float(np.mean([roc_auc_score(y[va], fuse_o[va]) for _, va in skf.split(np.zeros(len(y)), y)]))
```

`fuse_o` 是**已经用全体 y 造好**的分数向量。这里没有重新拟合任何东西，只是把它切成 5 段再平均
AUC。任何固定向量的分段 AUC 均值都必然 ≈ 全量 AUC。实测（`e1_repro_nested.json`）：

| 喂进去的向量 | 全量 AUC | 它的 "nested" | 差 |
|---|---:|---:|---:|
| v8_fuse（被审对象） | 0.770161 | 0.770330 | 0.00017 |
| v7_fuse | 0.758380 | 0.758510 | 0.00013 |
| 纯高斯噪声 | 0.499602 | 0.499742 | 0.00039 |
| **`y + 0.01*噪声`（100% 泄漏）** | **1.000000** | **1.000000** | **0.00000** |

把标签本身喂进这个"门禁"，它汇报 nested = **1.0** 并放行。
**该估计量对过拟合的检测能力为零**，v7/v6/v5 用的是同一段代码，整条 v4→v8 链的门禁全部无效。

另外 `random_state=2026` 正是 `TE_SEEDS` 的第一个 seed，切分与造 OOF 用的切分同源。

## 2. 符号翻转：用全体 y 定方向，再报同一份数据

`fuse_fp_v8.py:79`（`fuse_fp_v7.py:104` 同）：

```python
if roc_auc_score(y, oof) < 0.5:      # 用全体 y 决定方向
    oof = 1.0 - oof; tp = 1.0 - tp
seed_o.append(rankdata(oof) / len(oof))
```

每个键 × 每个 seed 都做一次这个判断。v7+v8 合计约 **1 700 个键 × 6 seeds ≈ 1 万次**用全体标签做的
二选一，然后把结果在**同一批标签**上评分。这就是在 14 930 行 / 1 496 个正样本上做 1 万次单侧选择。

对一个真实效应为 0 的键，样本相关系数 ~N(0, 1/√n)；取绝对值后再对上千个键求平均，
系统性地造出一个正的 AUC。这不是信号，是 |噪声| 的期望。

量化（`e2_crosshalf.json`，10 次 cross-half）：

| 键族 | 键数 | **诚实** cross-half | 不翻转 | **fp_v8 式全 y 翻转** | 翻转虚增 |
|---|---:|---:|---:|---:|---:|
| bit64 | 64 | 0.5015 ± 0.0101 | 0.5015 | 0.5719 | **+0.070** |
| withinbyte_bit_and | 224 | 0.5065 ± 0.0121 | 0.5065 | 0.5946 | **+0.088** |
| withinbyte_bit_xor | 224 | 0.5033 ± 0.0114 | 0.5033 | 0.6242 | **+0.121** |
| crossbyte_bit_xor（v7 的 cmean 主料） | 224 | 0.4925 ± 0.0087 | 0.4925 | 0.6243 | **+0.132** |
| withinbyte_tri_and | 448 | 0.5098 ± 0.0103 | 0.5098 | 0.6020 | +0.092 |
| bytepair_xor（v8 新增） | 28 | 0.4862 ± 0.0081 | 0.4862 | 0.5498 | +0.064 |
| bytepair_and（v8 新增） | 28 | 0.4995 ± 0.0038 | 0.4995 | 0.5462 | +0.047 |
| byte | 8 | 0.5089 ± 0.0096 | 0.5089 | 0.5307 | +0.022 |
| bytepair_concat | 28 | 0.4903 ± 0.0101 | 0.4903 | 0.5445 | +0.054 |
| *对照*：真实业务特征 x0..x18 | 19 | **0.5124 ± 0.0082（10/10 > 0.5）** | 0.5124 | 0.5408 | +0.028 |

键数越多，虚增越大（8 键 +0.022 → 224 键 +0.13），这正是选择偏差的指纹。
**虚增量随选择次数增长，而不随"信号"增长。**

## 3. 真 cross-half 迁移：id 各族全部为零

协议（`e2_crosshalf.py` / `e3_permutation_null.py`）：train 分半 A/B，**TE 表和符号全部只在 A 上定**，
冻结后应用到 B，A/B 对调，多 seed 重复。符号估计用了两种诚实做法：A 的样本内 AUC，以及
A 内部再做 5 折 inner-OOF（后者是这套想法的最强合法版本）。

结果：14 个 id 键族的诚实 cross-half AUC 全部落在 **0.486 ~ 0.512**，
"> 0.5 的次数" 基本是掷硬币（0/10 到 8/10）。**没有任何一族稳定为正。**

## 4. id 置乱对照：这是决定性的一条

把 train 的 id 列相对 y 随机置乱（`e3_permutation_null.py`，20 次置乱建 null 分布）后，
重跑完全相同的流程：

| 键族 | 诚实 cross-half（真 id） | 诚实（置乱 null） | **z** | p | fp_v8 式分数（真 id） | fp_v8 式分数（**置乱 id**） |
|---|---:|---:|---:|---:|---:|---:|
| byte | 0.5116 | 0.5025 | +1.53 | 0.143 | 0.5325 | **0.5257** |
| byte_hi | 0.4913 | 0.5007 | −1.23 | 0.905 | 0.5258 | **0.5241** |
| bit64 | 0.4978 | 0.5000 | −0.40 | 0.714 | 0.5748 | **0.5684** |
| bytepair_xor | 0.5071 | 0.5000 | +1.03 | 0.190 | 0.5498 | **0.5452** |
| bytepair_and | 0.4918 | 0.5027 | −1.35 | 0.952 | 0.5468 | **0.5468** |
| withinbyte_bit_and | 0.5039 | 0.4981 | +0.99 | 0.190 | 0.5964 | **0.5945** |
| crossbyte_bit_xor | 0.5034 | 0.5005 | +0.62 | 0.286 | 0.6249 | **0.6278** |
| withinbyte_tri_and | 0.5033 | 0.5027 | +0.10 | 0.429 | 0.6012 | **0.6050** |
| bytepair_concat | 0.4983 | 0.4985 | −0.03 | 0.476 | 0.5443 | **0.5436** |

两件事同时成立：

1. **诚实迁移的 z 全部落在 [−1.35, +1.53]，最小 p = 0.14。没有一族显著。**
2. **fp_v8 式分数在真 id 和随机置乱 id 上完全一样**（最大差 0.0067，全部在 null 波动内）。
   0.6249 vs 0.6278、0.5964 vs 0.5945、0.5748 vs 0.5684 —— 把 id 换成随机排列，
   它汇报的"信号"分毫不减。

> 一个在随机置乱数据上能一模一样复现的量，测的不是数据里的东西，是流程本身。

## 5. 基数与稀疏（为什么必然如此）

`e4_diagnostics.json`：train 14 930 行 / **正样本仅 1 496**，test 6 398 行。

| 键空间 | train 层数 | 每层行数 | 每层**正样本** | test 未见键比例 |
|---|---:|---:|---:|---:|
| bit（1 bit） | 2 | 7 465 | 748 | 0 |
| byte_hi（半字节） | 16 | 933 | 93 | 0 |
| byte | 256 | 58.3 | **5.8** | 0 |
| bytepair_xor / and | 256 / 249 | ~58 | **~5.8** | 0 / 0.05% |
| bytepair_concat | 13 371 | **1.12** | **0.11** | **80.3%** |

byte 级每层只有 ~5.8 个正样本，TE 的采样噪声 ~±0.12，而真实效应是 0。
bytepair_concat 每层 1.12 行、test 80% 是未见键 —— 这条在 test 上 80% 输出先验常数。

**最根本的一点**：`id` 是 16 位十六进制、64 bit。train/test 的 **id 交集 = 0**，
每字节均值 ≈ 127.5（期望 127.5），每 bit 均值 ∈ [0.492, 0.507]。
它是均匀随机哈希，且训练集里出现过的 id 一个都不会在 test 里再出现。
就算 id 真被"记住"了，也没有任何可搬运的载体。

## 6. 数据集诊断（顺带排除的几条）

* **对抗验证 train vs test AUC = 0.4965** → 同分布 iid 划分。没有分布漂移可利用，
  也意味着**本地诚实 CV 是可信的线上代理**。
* 训练集内无重复行，train/test 无重复行，无 group 泄漏。
* `days` 不是时间索引（test 的取值范围 100% 落在 train 内），划分不是时序的。

## 7. fp_v8 到底是什么

按权重展开配方，只有 **10.6%** 落在真正含标签信息的东西上：

```
fp_v8 = 0.80 * v7 + 0.20 * bytepair_mean
v7    = 0.15*v3 + 0.10*bits + 0.05*xs + 0.22*and_all
      + 0.06*tri + 0.06*or + 0.06*xor + 0.30*cmean
v3    = 0.55*am40(真 CatBoost) + 0.45*(id 键池)

真实内容 = 0.80 * (0.15*0.55  +  0.05) = 0.106
                    ~~~~~~~~~     ~~~~
                     am40         x 特征池
其余 89.4% 权重全部是 id 噪声池。
```

`bytepair_mean`（v8 相对 v7 的**全部**新增内容）与 W62 的 Spearman = **−0.030**。
它和真实信号正交，不是因为它带来了新信息，**是因为它是噪声**。

fp_v8 与 vz19 的 Spearman 0.9170、与 W62 0.9077 —— 它确实"和已交的不一样"，
但这个不一样完全来自往一个 CatBoost 底座上泼随机扰动。
**"和已交文件不同"和"更好"是两件事，fp_v8 只满足前者。**

### 线上预期

fp_v8 的排序 ≈ am40/W62 家族被噪声扰动后的版本（Spearman 0.908，注入噪声占最终提交方差的 ~9%）。
噪声与标签独立，只会拉低期望 AUC。

**预期线上 0.705 ~ 0.713，几乎不可能超过 W62 的 0.71503，冲前三 0.72 的概率极低。**

## 8. 顺带：vz19 里也有同一个病灶

`src/build_vz19.py` 的最终配方是 `(1-w)*max2 + w*byte07`，`w_te ≈ 0.11`，
而且 `w_te` 是在**全体 OOF 上扫出来的**（`build_vz19.py:120-125`）。

`byte07` 就是 byte0/byte7 的 TE。本审核测得 byte 族诚实 cross-half **0.5116，
对置乱 null 的 z = +1.53，p = 0.14，不显著**。
`docs/EVIDENCE.md` 自己也记录了：在从未参与调参的 outer seed 90210 上，
vz19 的另一个组件 max2 的增益是 **−0.00007**（文档原先声称 +0.00176）。

**vz19 线上 0.71298 < W62 线上 0.71503，两者 Spearman 0.9949 —— 这 0.002 的差距，
方向上正好和 vz19 多带的那 11% 噪声一致。** 这条已交结果本身就是"往好底座上加 id 噪声会掉分"的
一次线上实测。

## 结论

| 检验 | 结果 |
|---|---|
| nested 是否真 nested | ❌ 是把成品 OOF 再切片；喂标签进去它报 1.0 并放行 |
| 是否存在全 y 符号翻转泄漏 | ❌ 约 1 万次全标签单侧选择，虚增 +0.02 ~ +0.13 |
| id 组件真 cross-half 是否为正 | ❌ 14 族全部 0.486~0.512，无一稳定 |
| 置乱 id 后是否失效 | ❌ **完全不失效**，逐位复现（最大差 0.0067） |
| 是否有可迁移的 id 结构 | ❌ train/test id 交集 = 0，均匀哈希 |
| 声称的 0.77016 | ❌ 真实可迁移水平 ≈ 0.70（即底座 am40 本身） |

**不要提交 fp_v8。** 它的 0.77 是 1 万次全标签方向选择在自己身上留下的印子。
替代方案见 `VZ21_METHOD.md`。
