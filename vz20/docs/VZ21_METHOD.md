# vz21 方法与门禁

配套：过拟合证据见 `FP_V8_AUDIT.md`，数字见 `artifacts/vz20/{fp_v8_audit,vz21_*}.json`。

## 0. 先说结论（不好听，但是实测出来的）

我按要求做了替代方案，也做出了两个文件。但必须先把这一轮最重要的发现说清楚：

> **在这份数据上，"和已交文件 Spearman < 0.97" 和 "线上超过 0.71503" 这两个要求，
> 基本是互斥的。不是因为我懒，是因为我把这条代价曲线量出来了。**

所有诚实模型都会收敛到同一个排序。我独立造了 **3 个特征世界 × 5 个模型家族 = 12 条臂**
（CatBoost Ordered/Plain/Logloss、LightGBM、XGBoost、ExtraTrees、逻辑回归），
在 4 个全新 outer seed 上跑完 240 个模型。结果：

* 没有任何组合能在**未参与筛选的 seed** 上超过 vz19 内核，最好的一个是 **+0.00012**；
* 每一个诚实融合对 W62 的 Spearman 都 ≥ **0.993**；
* 连一个完全不同类的模型（逻辑回归，AUC 只有 0.654）对 W62 都还有 **0.873**。

**两个好模型在同一份数据上必然互相同意。** 想让 Spearman 掉到 0.97 以下，
唯一办法是把分数弄差 —— 这正是 fp_v8 干的事，只不过它用的是噪声。

## 1. 设计原则（针对审出来的每个病灶）

| fp_v8 的做法 | vz21 的做法 |
|---|---|
| 把成品 OOF 切五块当 nested | seed 分两组，**CONFIRM 组从头到尾没参与任何筛选**，只在最后看一次 |
| 用全体 y 定 1 万次符号 | 不存在符号选择；一切编码折内完成 |
| 逐步在污染 OOF 上堆 v4→v8 | 融合权重是**预注册规则**，不是在评分数据上搜出来的 |
| 重度 id TE | **完全不用 id**，一个 bit 都不用 |
| 门禁 = "比上一版 OOF 高" | 门禁 = 在未动过的 seed 上**配对**比 vz19 内核高 |

seed 分工（写死在 `src/vz21_arms.py`，跑之前定的）：

```
SELECT_SEEDS  = (424242, 515151)   臂筛选 + 融合构造
CONFIRM_SEEDS = (737373, 848484)   只在最后开一次
```

## 2. 十二条臂

三个特征世界：

* `main` —— vz19 的 `build_main`，121 特征 / 81 类别（region×source×age×days×condition 交叉骨架）
* `alt` —— vz19 的 `build_alt`，rate 世界，73 特征 / 48 类别
* `new` —— 本轮新建（`src/vz21_pipeline.py`），79 特征 / 34 类别，
  解析 `t3` 为 数值+后缀 而不是 163 层裸类别，ratio 与 rate 两个世界合并

五个模型家族，各自折内建模；LightGBM / XGBoost / ExtraTrees 用**折内 OOF 目标编码**
（`vz21_models.te_encode`，训练行用内层 OOF，验证/测试行用训练部分拟合的表）。

## 3. 预注册融合规则与门禁结果

五条规则在看到任何融合分数**之前**写进 `src/vz21_blend.py`
（`P5_family_all` 是在 SELECT 臂分数出来后、任何融合分数算出来前加的，动机是主人给的多样性约束，
已在代码注释中标注）。质量门槛 0.675 也是预先写死的。

| 配方 | SELECT | **CONFIRM（未动过）** | Δ vs vz19 内核 | 逐折战绩 |
|---|---:|---:|---:|---:|
| BASE_vz19core (0.64/0.36) | 0.69315 | **0.69694** | — | — |
| P1_equal | 0.69309 | 0.69641 | −0.00053 | 6/10 |
| P2_family | 0.69263 | 0.69619 | −0.00075 | 6/10 |
| P3_quality | 0.69322 | 0.69641 | −0.00053 | 5/10 |
| **P4_core_plus** | 0.69351 | **0.69705** | **+0.00012** | **7/10** |
| P5_family_all | 0.68996 | 0.69353 | −0.00341 | 2/10 |

再做一次对照实验：在 12 维单纯形上**随机搜 2 万组权重**最大化 SELECT fold-mean，
得到 SELECT 0.69406（比 P4 高 0.0006），但在 CONFIRM 上只有 **0.69632，反而比 vz19 内核低 0.0006**。

> **预注册规则迁移了，搜出来的权重没迁移。** 这就是 fp_v8 那条路的小型复现，
> 只不过我们提前用 CONFIRM seed 抓住了它。

**门禁裁决：融合带来的真实增益 = +0.0001，统计上等于 0。CatBoost 家族确实到顶了。**

## 4. 我另外排除掉的几条路（都是负结果，但省得下次再走）

| 假设 | 实测 | 结论 |
|---|---|---|
| x0..x18 这 17 列被 vz19 完全丢弃，也许有金子 | 单独建模 AUC 0.512；加进特征集 **−0.0041** | 是噪声，丢对了 |
| `t3` 是最强特征（边际 AUC 0.601） | 那是 163 层裸 TE 的样本内虚高；数值部分只有 0.513，分位数非单调 | 假的 |
| train/test 有分布漂移可以利用 | 对抗验证 AUC **0.4965** | iid，没有 |
| `days` 是时间戳 / 有周期结构 | test 取值 100% 落在 train 内；mod 7/30/365 全部 ≤ 0.516 | 没有 |
| 有重复行 / group 泄漏 | train/test 精确重复 **0** 行 | 没有 |
| 手写交叉太多导致过拟合，精简会更好 | 去掉交叉 **−0.0271** | 反了，交叉是发动机 |
| CatBoost 的 `max_ctr_complexity` 默认 4 没调过 | ctr=1 **−0.011**，ctr=2 −0.0014，ctr=6 −0.0005，**ctr=4 最优** | 默认已最优 |
| 换模型家族能带来正交增益 | LGBM/XGB/ET/GLM 全部 0.65–0.68，融合后 +0.0001 | CatBoost 的类别组合无可替代 |

第 6 行和第 8 行合起来解释了这份数据的性质：**信号几乎全部藏在类别交互里，
而 CatBoost 的 CTR 组合机制是目前唯一能有效榨取它的工具。** 这也是为什么所有解都长得一样。

## 5. 多样性的价格（核心图表）

`src/vz21_frontier.py`：从最强诚实融合出发，逐步把权重挪给最不相关的诚实臂。

| α（挪给多样臂的权重） | 本地 fold-mean | Δ | rho(W62) | rho(vz19) |
|---:|---:|---:|---:|---:|
| 0.0 | 0.69376 | +0.00000 | 0.9961 | 0.9901 |
| 0.3 | 0.69054 | −0.00322 | 0.9928 | 0.9861 |
| 0.5 | 0.68702 | −0.00674 | 0.9868 | 0.9797 |
| **0.8** | 0.68000 | **−0.01376** | **0.9718** | 0.9641 |
| 1.0 | 0.67420 | −0.01955 | 0.9577 | 0.9497 |

对照组 —— 用**纯噪声**买多样性（fp_v8 的做法）：

| 噪声权重 | 本地 fold-mean | Δ | rho(W62) |
|---:|---:|---:|---:|
| 0.0 | 0.69376 | +0.00000 | 0.9961 |
| 0.2 | 0.68694 | −0.00681 | 0.9815 |
| 0.3 | 0.67603 | −0.01772 | 0.9561 |
| 0.4 | 0.66283 | −0.03093 | 0.9040 |

**两条路的价格几乎一样：想把 rho 压到 0.97 以下，就要付出约 −0.014 到 −0.020 的 AUC。**
而 W62 到前三线只差 +0.005。**多样性的代价是这个差距的 3 倍。**

fp_v8 的 rho(W62) = 0.9077，对应噪声权重 ≈ 0.4 那一档，
这就是我给它 **线上 0.685–0.705** 这个区间的依据。

## 6. 榜单噪声（为什么不该赌）

test 只有 6 398 行、约 640 个正样本。Hanley–McNeil 单个 AUC 的标准误 = **0.0118**。

| 差距 | 值 | 折合 SE |
|---|---:|---:|
| W62 → 前三线 0.72 | +0.00497 | **0.42 SE** |
| W62 → 冠军 0.749 | +0.03397 | 2.87 SE |
| vz19 → W62 | +0.00205 | 0.17 SE |

前三线只在 W62 上方 0.42 个标准误 —— 这个距离**靠一个稍好的模型是够得着的，
靠把文件弄得不一样是够不着的**（因为后者要先倒退 1.2 个 SE）。

两份高度相关提交之间的差值精度高得多（rho=0.99 时 SE(diff)≈0.0017），
所以 **+0.002 的真实改进是可以被榜单分辨出来的**，而 −0.014 的倒退也一样会被分辨出来。

## 7. 两个产出文件

两份都不含任何 id 特征，都由 **4 outer seed × 5 折 = 每条臂 20 个模型**的测试预测平均而来。

### `next_submit/submission_vz21.csv` —— 主推荐

配方 = 预注册的 `P4_core_plus`，唯一在未动过的 CONFIRM seed 上非负的规则：

```
vz21 = 0.60 * (0.64*A_main_ord + 0.36*A_alt_plain)        # vz19 内核
     + 0.40/6 * (B_main_plain + B_alt_ord + C_main_ll
                 + C_main_deep + D_new_ord + D_new_plain)  # 六条其它臂等权
每条臂先 rank 归一化；最终分数再 rank 归一化后 clip 到 [0.001, 0.999]
```

* SELECT 0.69351 / **CONFIRM 0.69705**（vz19 内核 0.69694，Δ **+0.00012**，7/10 折胜）
* rho(W62) **0.9980**、rho(vz19) 0.9926
* 背后 8 臂 × 20 = **160 个模型**，比任何单一 pipeline 方差更低
* **期望线上 0.713 ~ 0.719**

**它没有通过主人给的 Spearman < 0.97 这条线。我没有假装它通过。**
理由在第 0、5 节：能通过那条线的东西，期望分数都在 0.70 附近。

### `next_submit/submission_vz21_div.csv` —— 满足多样性约束的版本（高风险）

在 `rho ≤ 0.965` 约束下最大化 SELECT fold-mean 搜出来的权重
（rho 用测试预测算，不含标签，搜它不会泄漏）：

```
vz21_div = 0.502*F_new_glm + 0.279*C_main_deep + 0.217*B_main_plain + 0.002*C_main_ll
```

* CONFIRM **0.68234**（比 vz19 内核 **−0.01460**）
* rho(W62) **0.9636**、rho(vz19) **0.9560** —— **通过** Spearman < 0.97
* **期望线上 0.698 ~ 0.705**，超过 0.71503 的概率我估计 **< 5%**

它唯一的价值是"确实是一份不一样的文件"。**我不推荐交它**，
但如果主人坚持这一轮必须换轴，这是所有换轴选项里最好的一个 ——
至少它的多样性是用**真模型**换的，不是像 fp_v8 那样用噪声换的。
